# CLAUDE.md — context for AI coding assistants

This file exists because the ARK website is maintained by a **volunteer committee
that may have no developer in any given year**. If you are an AI assistant helping
someone here, assume the person you are helping is a committee member, not an
engineer. Explain things plainly, prefer the smallest safe change, and never
suggest a redesign when a content edit will do.

Human-facing documentation:

- `README.md` — short repo guide
- `docs/project-handover.md` — the main maintenance and yearly handover guide
- `docs/deployment-handover.md` — deployment ownership and access

## What this is

The website of **ARK — Association of Rogaland Keralites**, live at
<https://kerala.no>. Next.js 16 App Router, React 19, TypeScript (strict),
Tailwind CSS 3, deployed on Vercel. Content is Markdown on disk; there is no CMS
and no database.

## Commands

```bash
npm install       # first time
npm run dev       # http://localhost:3000
npm run lint      # ESLint
npx tsc --noEmit  # type check
npm run build     # production build + sitemap generation (postbuild)
```

All three of `npm run lint`, `npx tsc --noEmit`, and `npm run build` must pass.
`.github/workflows/ci.yml` runs exactly those on every pull request, so a red
check means one of them fails locally too.

## Which files are safe for a non-developer to edit

Safe:

- `content/events/` — one Markdown file per event
- `public/images/events/` — gallery photos
- `src/lib/metadata.ts` — email, location, org number, social links
- `src/lib/committee.ts` — committee names and roles
- `src/lib/messages/{en,no,ml}.ts` — all website text
- `docs/`

Developer-only:

- `src/app/`, `src/components/`, `src/lib/events.ts`, `src/lib/i18n*.ts`
- `next.config.mjs`, `next-sitemap.config.js`, `tailwind.config.ts`,
  `eslint.config.mjs`, `package.json`, `.github/workflows/`

Never edit by hand: `public/sitemap.xml`, `public/sitemap-0.xml`,
`public/robots.txt`. They are generated by `next-sitemap` during `npm run build`
and are gitignored. Never commit secrets; `.env.local` and `.vercel/` are
gitignored and must stay that way. The only credentials this project uses are
GitHub Actions secrets (`VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID`).

## How the three languages work

There are no `/en` or `/no` URL prefixes. Every page reads the visitor's locale
per request, in this priority order:

1. the `ark-locale` cookie — set only when the visitor picks a language manually,
   remembered for a year
2. the `Accept-Language` request header — the languages configured on the
   visitor's device, so a phone or browser set to Malayalam gets Malayalam
   automatically on the first visit, with **q-values respected**, not just list
   order
3. `en`

Files:

- `src/lib/i18n.ts` — `locales` (`en`, `no`, `ml`), display names, date/OG locale
  mapping, and `matchPreferredLocale()`. `localeLanguageTags` maps each locale to
  the language tags that should match it — Norwegian accepts `no`, `nb` and `nn`.
  Matching is on exact tag or `tag-` prefix, so `ml-IN` → `ml` and `nb-NO` → `no`.
- `src/lib/i18n-server.ts` — `getRequestI18n()`, and the `Accept-Language` parser
- `src/components/LanguageSwitcher.tsx` — writes the cookie, then `router.refresh()`

A website can only see the visitor's configured *display languages*. Installed
keyboards, fonts, and OS region are not exposed to the browser — if someone asks
for "detect their Malayalam keyboard", `Accept-Language` is the real mechanism.

Every page calls `getRequestI18n()`, which calls `cookies()`. **That makes every
route dynamically rendered** (`ƒ` in the build output). Consequences worth knowing
before you "optimise" anything:

- `generateStaticParams` in `src/app/events/[slug]` and
  `src/app/events/gallery/[category]` is therefore inert. Leave it or remove it;
  it does not make pages static.
- `export const revalidate = ...` on a page does nothing here. Do not add it.
- Making the site static would mean moving every route under `/[locale]/` and
  rewriting all internal links. That is a real project, not a quick win. Do not
  start it unless the person asking is a developer who has agreed to the scope.

Message files:

- `en.ts` is the source of truth and defines the `TranslationMessages` type.
- `no.ts` and `ml.ts` both end with `as const satisfies TranslationMessages`, so
  **all three languages are complete and cannot drift** — adding a key to `en.ts`
  without adding it to the other two is a type error that fails the build.
- `ml.ts` previously used a partial object deep-merged over English, which meant
  a missing key silently rendered in English with no warning. Roughly half the
  site was affected. **Do not reintroduce that pattern.** If Malayalam text is
  genuinely unknown for a new key, put a placeholder in and open an issue —
  do not make the object partial again.

Message values are **plain text, not Markdown**. Writing `**bold**` in a message
file puts literal asterisks on the page — this was a real bug on the committee
page. Use markup in the component instead.

## Events and galleries

`src/lib/events.ts` is the whole content layer; it reads the filesystem at
request time.

- Events: `content/events/<slug>.md`. The filename becomes the URL
  (`/events/<slug>`). Frontmatter: `title`, `date`, `venue`, `category`,
  `featured`, `excerpt`. Body is rendered with `next-mdx-remote`, styled by the
  `.ark-prose` rules in `src/app/globals.css`.
- `date` must be `YYYY-MM-DD`. `getAllEvents()` **throws and fails the build**
  on a malformed or impossible date, naming the file. This is deliberate: a
  failed build is much better than publishing "Invalid Date". Do not soften it
  into a silent fallback.
- `featured: true` pulls an event to the front of the homepage preview via
  `getFeaturedUpcomingEvents()`. Every frontmatter field must actually be read
  by something — `month` and `featured` were both previously dead, which sent
  maintainers chasing changes that could not possibly have any effect.
- There is no `month` frontmatter field. Month labels come from `date` via
  `formatEventMonthForLocale`. Do not reintroduce a `month` field.
- Upcoming vs past is decided by comparing `date` against today in UTC.
- Event bodies are **English only in every locale**. There is no per-language
  event content.
- Galleries: `public/images/events/<folder>/`, mapped to route segments by
  `galleryGroupFolderCandidates` / `galleryGroupRouteSegments` in `events.ts`.
  Only `.jpg .jpeg .png .webp .avif` appear; videos (`.mov`, `.mp4`) are ignored
  entirely. A category appears on `/events` only if its folder has at least one
  supported image. `galleryGroupFolderCandidates` deliberately includes
  misspelled folder names (`easte-vishu-eid`, `other-acitivites`) so that
  historical typos keep working — do not "tidy" those away.

`public/images/` is around 79 MB, including a 12 MB `.MOV` that is never
displayed and JPEGs up to 10.8 MB. Compress new photos before adding them.

## Conventions to follow

- Colours are hex literals in inline `style` props (`#1a3a2a` dark green,
  `#c8922a` gold, `#e8b84b` light gold, `#f5f0e8` cream, `#3a6b8a` fjord blue).
  Tailwind `ark-*` colour aliases exist in `tailwind.config.ts` but most of the
  code does not use them. Match the surrounding file rather than converting.
- **Contrast rule for gold.** `#c8922a` on the cream/white backgrounds measures
  only **2.8:1** and fails WCAG AA for body-size text. Use `#7d5915`
  (`ark-gold-text`, 5.2–6.3:1) for small text on light backgrounds, `#e8b84b`
  for small text on dark backgrounds, and keep `#c8922a` for large display text,
  borders, icon tints, and button fills. Do not reintroduce `#c8922a` as a text
  colour on a light background.
- Pages are server components. Only `Nav`, `LanguageSwitcher`, `AnimateOnScroll`,
  and `EventGalleryLightbox` are `'use client'`.
- All user-visible strings come from message files. Never hardcode English in a
  component, and never hardcode the ARK email — use
  `siteConfig.contact.email` from `src/lib/metadata.ts`.
- `FormattedInlineText` bolds the word "naattile" **by default, everywhere** it
  is used, which includes every `SectionHeader` intro and every event excerpt.
  This surprises people; see the comment in that file.
- Keep accessibility as-is or better: `aria-label` on sections, `aria-hidden` on
  decorative SVGs and emoji, visible focus rings. `EventGalleryLightbox` handles
  Escape and arrow keys but does not trap focus — a known, unfixed gap.

## Known gaps, deliberately not fixed

Documented so they are not rediscovered as surprises:

- Whole site is dynamically rendered (see the i18n section above).
- Gallery lightbox has no focus trap or focus restore.
- `/events` calls `getAllEvents()` more than once per request. Irrelevant at
  three event files; would matter at a hundred.
- Large uncompressed images in `public/images/`.
